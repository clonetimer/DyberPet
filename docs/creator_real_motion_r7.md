# DyberPet R7 · 真实原画逐帧运动质量核查

本轮定位真实桌宠“人物看起来是立牌，而且爬行/下落只是移动一张静止图”的问题：**不能以动作文件名、PNG 数量和文件存在代替真正运动姿态证据**。在 R6 65 人物／67 套作者素材基线上，新增不改图的原始全帧差异统计和用户可见提示。

## 真实素材全面检查

实际运行：`clonetimer/ChatGPT-Download` 的 [R7 作者原图审计](https://github.com/clonetimer/ChatGPT-Download/actions/runs/40370272681)。

| 证据 | 实测值 |
|---|---:|
| 实际扫描版本 | 67 |
| 成功读取版本 | 67 |
| 有姿态变化风险的版本 | 14 |
| 有风险的动作序列 | 28 |
| 无法读取的版本 | 0 |
| 自动认定 Q版或动作质量合格 | 0 |

目前发现的 28 个行动风险**均属 crawl 和 fall 动作各仅有一帧**，涉及 14 套作者素材：安柏、菲谢尔、旅行者（空）、阿贝多、达达利亚、重云、迪卢克、凯亚、枫原万叶、旅行者（荧）、雷泽、托马、温迪、钟离。这不是声称他们所有动作都差，而是从真实内置作者素材提取出的可复核缺口。带静止人物姿态的单帧也可能随物理窗口移动，但没有连续改变的人物姿态。

## R7 相比 R4 的检测纠偏

R4 的弱运动风险只检查某些动作的第一、第二帧。R7 会在固定帧数和尺寸上限内解码**每一帧**。计算人物非透明包围框，比较扣除空白边缘后的真实 RGBA 人物像素，而不是把整个图层平移或透明画布补齐误算为新的动作姿态。

额外提供以下**人工复核线索**：动作只有一帧；多帧但人物图像完全相同（可能只是位置变化）；连续三帧以上形象一样；存在完全透明帧。没有命中这些规则也不能证明动作自然、角色形象符合原设或声音一致。

## 用户端查看与判断

R7 的逐帧动作预览窗口在选择原生动作后显示当前动作的真实帧数、不同可见人物姿态数以及风险说明。例如：“5 帧、1 个姿态；所有帧人物姿态相同，可能只是平移立牌”。如质量统计暂不可用，仍允许用户逐帧查看来源原画，不会禁用原本可以播放的作者动画。

真正补齐一帧的 crawl/fall 不可能凭空“生长出原作者创作的下一张画”。后续只能从匹配人物的新来源素材获得多姿态动作，并核验角色授权与原设；不能简单复制图片或画简笔画凑帧。软件可播放该动作，但必须明确展示“单帧”。

## 验收边界

- Windows/Linux 专项测试覆盖透明位移误判、首两帧相同但后面变化、长重复动作及安全拒绝。
- 真实 67 套资料只在 Actions 隔离临时目录读取，输出 JSON 统计，不上传原始第三方图片。
- R7 不增加独立角色数量，不自动升级 Q版合格数，也不默认更换用户现在的素材。
- 若 Python/Rust 独立 ZIP 尚未全部通过并上传，R6 仍是可以安装使用的最新个人版；不要把仅源码 PR 冒充已发布新版。
