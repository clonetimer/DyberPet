# R52：Doro 优先——在 DyberPet 内直接播放本机 Live2D 原画

## 解决的实际问题

R7 的 Doro 是其他画师的旧版 PNG 图集，并不是用户认可的 **六碳糖（0x4682B4）四足 Dororong Live2D**。继续只改 R7 的 PNG 播放参数，无法让旧角色变成这套原设。因此 R52 新增**真正的 Live2D 模型运行时预览**，不是生成新的 Doro 画像，不是使用其他作者素材拼贴，也不是增加更多角色模板。

- 使用 EasyLive2D/live2d-py 的原生 Cubism 3+ PySide6/OpenGL 引擎。
- 直接加载本机的 .model3.json 和作者原始资源，实时 Update/Draw；支持原模型登记的动作与表情、鼠标视线跟随，**不裁切导出源图**。
- **新增真正的独立桌面 Doro 置顶窗口**：从 Live2D 预览界面点击“在桌面独立运行”，左键拖动（按系统最小拖动阈值防误触）、轻点触发原生随机表情、右键菜单列出原生表情/动作、滚轮缩放、关闭清理。独立运行窗口不要求先保存 PNG 图集。
- 角色管理 → 咕嘎 / Doro → “【Doro 专项】用已取得的四足 Live2D 原模型预览”。第一次选择本地 model3.json 路径，以后由本机 QSettings 记住路径；不会缓存模型字节。
- Windows 便携构建预装 live2d-py==1.0.0 与 PyOpenGL==3.1.10 动态引擎（没有作者模型）。不要求用户自行安装开发环境或编译引擎。
- 严格检查 Moc3、纹理、Motion3、Expression3、Physics 等模型资源引用；拒绝路径穿越、远程链接、缺失文件和过大资源，预览始终只读。
- CI 使用测试假的模型文件名和内容核对本机文件引用及模块导入，不复制授权受限的 Dororong 模型。

## 美术与授权边界

[原作者作品页](https://booth.pm/zh-cn/items/5867617) 列出免费 Live2D 模型，**禁止模型再分发及用于 AI 生成艺术**。本功能只提供播放引擎；没有把第三方模型放进 public DyberPet 或 private ChatGPT-Download，也没有从其他作品再生成所谓“新 Doro 原画”。

[MelanTech/Dororo](https://github.com/MelanTech/Dororo) 是实际互动参考，其代码/展示与原作者作品的美术再分发权利不同，不直接复制作者二创模型。

## 尚未宣称完成的部分

1. 本轮是**内嵌 PySide6 Live2D 预览＋独立置顶 Doro 桌面窗口**，但尚未替换 DyberPet 原有的统一桌宠状态机（任务/互动等），不等于已有全部角色功能完整覆盖。
2. 原始 Live2D 动画项目仅登记 10 个表情、1 段动画；不能凭空写成已做成完整四足爬行、抓取、摸头、休眠、跌落等独立动作。
3. Cubism 2D 模型不是独立正交正、侧、背三视图。背视图仍缺失，禁止镜像充数。
4. 源许可禁止再分发，因而**没有可直接公开或私有上传的含原作者 Doro 美术的自包含 ZIP**。
5. 真实 Windows 本机运行和目标模型美术验收需实际模型+GPU/驱动验证；CI 可以验证代码、依赖及空模型门禁，却不能自动签核美术。

## R53：单角色稳定性与 Live2D 真实进度检查

- **单实例桌宠**：重复点击“在桌面独立运行 Doro”只激活同一个 Live2D 窗口；更换模型会关闭旧实例，不再同时占用多个 GPU 上下文。
- **失败可见**：Cubism 模型/动作文件加载失败会给出错误提示并停止渲染定时器，不把黑屏当作成功。
- **本地更换模型**：预览窗口新增“更换本机 Live2D 模型文件”，不要求删除设置或复制任何第三方素材。
- **验证实际动作**：`OwnerIdle` 的 `LoadExtraMotion` 调用后检查运行库登记的动作组，只有真实加载成功才称可播放。
- **单角色完成门禁**：新增原生 Live2D 入口 `python tools/doro_single_role_gate.py --live2d-model "Doro.model3.json" --out DORO_STATUS.json`；显示本机资源、表情、原生动作以及缺失的三视图、四足动画、Windows 实机和授权证据。即使引擎工作正常，报告仍然 **complete=false**，直到实际通过完整验收。

这轮**没有补画或声称完成独立三视图**，也没有修改 0x4682B4 模型的图像内容。


## R54：真模型命中区与双窗口 OpenGL 修复

这是 **Doro 单角色** 的继续收敛，未增加新角色、绘画或导出任何第三方模型。

- **引擎重复初始化修复**：预览和桌面窗口会分别创建 QOpenGLWidget。live2d-py 的 `glInit()` 是进程级后端初始化，不能每打开一个窗口重复调用。R54 只初始化一次，并在 DyberPet 创建 QApplication 之前启用 Qt `AA_ShareOpenGLContexts`，让两个窗口具备共享 OpenGL 资源的必要条件。
- **原画命中区域**：作者 Doro 模型在 `HitAreas` 中登记 `HitAreaFace` 和 `HitAreaLegBack`。R54 使用 Cubism `IsAreaHit` 判断按下/抬起是否命中相同部位；只有该模型本身具有原生表情时才反馈。脸部点击优先原生 `Amaze`，后腿点击优先 `Doubt`，其他不存在的表情不会生成。
- **透明区域不触发反馈**：点空白不再触发 R53 的随机表情；鼠标离开按下区域、不算点击。窗口只有按在真正可见的源模型绘制区域（由 `HitDrawable` 验证）时才开始拖动；不改动作源文件。
- **仍然只是原生表达反馈**：`Amaze` / `Doubt` 是作者已有表情，**不是承诺存在额外的摸头逐帧动作，也不是完整四足跑步、睡眠或独立背面三视图**。
- **测试**：本地模型 JSON 假数据 + Qt offscreen 真实鼠标事件，验证脸/后腿/透明背景、身体拖动、双窗只调用一次 GL 初始化；Windows 便携包另做 PyInstaller 及启动 smoke。

如角色模型版本不同、没有对应 `HitAreas` 或表情，本程序不会将相似名称当作已有动作。R51 完成门禁仍维持未完成状态，直到独立美术、动作、Windows 实机和交付权利全部有真实证据。
