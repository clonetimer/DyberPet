# R47：真实桌宠窗口 Q版原画稳定画布

## 问题

此前 R43/R44 的三视图可见轮廓对齐只在原画**审查窗口**生效。真实 `PetWidget.set_img` 每换一张原作者 PNG 都根据这张图片的宽高调整 `QLabel` 的大小。原画帧透明画布大小有差异时，会导致桌宠本体从待机切到走路、摸头或技能时视觉重心跳变。

## 本轮修复

- 新增 `tools/native_sprite_canvas.py`：扫描当前加载角色的原生 `PetConfig.act_dict`，仅在源 PNG 的**画布尺寸确实不一致**时，建立**每段完整动作统一**的 alpha 可见轮廓锚点。相同尺寸、原作者已对齐的 PNG 直接沿用原先的绘制方式，不干预作者主动设计的动作。
- 真正的桌宠主窗口 `PetWidget.set_img` 统一使用与角色素材相适配的透明画布，保持宽高稳定，原作者每帧 QPixmap 只作**内存显示平移**，不修改或重新生成磁盘上的图像。
- 固定的是**整段动作共同的锚点**，而不是每一帧各自对齐脚底。因此角色实际跳跃、悬浮、身体起伏、眨眼等源动画变化依然保留。
- 角色切换时重新构建当前角色的画布数据；仅保留最多 8 帧的渲染缓存，避免 65+ 角色源码帧造成无界内存积累。对异常大图与过量帧默认不启用该功能。
- 修复结果与已有 R45 专属动作、R46 鼠标摸头/拖动共用真实 `PetWidget`。不需要用户重新安装任何角色素材。

## 验收

新增 Qt 回归验证：128×128 与 256×256 的不同透明留白源图、相同可见身体经过实际 `PetWidget.set_img` 后必须呈现同样大小和固定画布；跳跃组显示保留 50px 高度变化；普通统一画布原画不能被改动；超大 PNG 不会诱发异常渲染内存使用。

跨平台单元测试和 Linux/Windows 可执行程序构建通过后再合并主干。

## 限制

这个修正是**真实角色显示比例与运动衔接的技术修复**，不等于补全真正的原设正/侧/背三视图，也不自动认证画师风格一致性。**私有 R7 65 角色全量原画完整包**尚未与新源码重新合并，不把仅有公开 EXE 的工作流误报为完整原画包已交付。
