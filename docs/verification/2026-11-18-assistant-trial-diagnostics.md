## 行为验证与审阅修复

新增组件均先写失败回归。标准库记录器和独立 Qt 窗口实现后通过；首轮集成 12 项通过，后续审阅新增 4 项明确失败的回归并修复：

1. **停止不能被排队成功覆盖。** 让 TTS worker 先返回 True、暂不处理 Qt 成功信号，再点击停止；原界面仍显示完成。修复后界面和记录均保持停止，实际驱动完成可作为独立观测保留。
2. **操作停止不是负的驱动完成回调。** 真实 `speak_interruptible` 配合受控 `pyttsx3.init`，在准备阶段停止时未观察到完成事件，报告应为 null。驱动明确回调 False 时通过类型受限的异常元数据传递 False；完成后又抛异常也保留已观察值和原始 cause。
3. **缺配置提示必须在前景可见。** 试用窗口缺模型或 Vosk 目录时直接给出下一步提示；没有接受 worker 的尝试不伪造操作记录。

独立审阅未发现 Critical 问题；上述两个 Important 和一个 Minor 均处理。另检查并修正诊断窗口的共享服务提示，避免把 PPL 地址问题引导为模型配置问题；语音配置标签使用“初检”，不宣称设备已通过。

隐私回归在普通输入、历史、记忆、PPL、附件、角色、模型 ID、路径及异常中注入不同秘密哨兵，确认它们不进入报告。实际回环 HTTP 验证试聊请求仅含系统消息和固定用户请求；真实 Qt worker 验证取消、模型/地址往返编辑、角色变化、关闭、语音就绪、最终转写与导出失败隔离。

## Qt 6.8 原生崩溃的完整处理

首轮 Python 3.11 / Qt 6.5 的 788 项完整回归通过；Python 3.12 / Qt 6.8 首轮在旧 setup 测试的事件循环中 exit 139。该位置早于任何 TrialDialog 测试。

通过 faulthandler、固定 61 项序列和 GC/弱引用追踪确认：旧文件夹授权测试的 MagicMock 调用记录持有父窗口，close 后 wrapper 延迟到 HTTP 工作线程的 GC 才释放，下一次 Qt 事件循环崩溃。单窗口引用环/worker GC 的最小脚本也重现同因果链。

修正仅涉及 `test_assistant_qt.py` 的该用例四个固定返回选择器，改为不保留调用记录的函数替身。原授权、文件创建和重置断言保留。原顺序 61 项与追踪版本都通过，窗口改为在自身用例结束时于 MAIN 线程释放；随后两套完整 797 项回归通过。没有关闭 GC、重排测试、跳过测试或用生产改动掩盖夹具问题。

## 资源与构建身份

记录器使用实际进程 CPU 时钟、Linux 驻留页数 × 页大小、Windows 当前 WorkingSetSize。Windows 的 ctypes 结构需缓存复用，重复创建类型造成 POINTER 缓存增长已先复现后修正。平台 API 边界通过受控测试；Linux 另执行真实只读采样，Windows 原生调用留给相应平台执行。
