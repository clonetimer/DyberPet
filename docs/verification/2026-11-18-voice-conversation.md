# 轮流语音对话与原生反馈：验证记录

日期：2026-11-18。分支：`feat/ai-companion-runtime-20261117` / [PR #99](https://github.com/clonetimer/DyberPet/pull/99)。接续基线为 `c460a95c3a6b2ae1f6baf1a5c8be9e1c11833ffd`。本记录保存本批实现与本地证据；发布后的精确提交、工作流和新 Windows 候选包在 PR 的本批 Validation 更新。

## 已实现的用户流程

- 显式“开始语音对话”，监听一句后自动请求现有本地流式聊天、朗读、再听；同一会话只加载一次 Vosk 模型。
- “打断，继续听”先停止旧任务，再开始监听；“结束语音对话”撤销所有排队后继。现有各阶段停止按钮结束本场。
- 语音控件固定在滚动区上方，阅读历史或底部操作时仍可打断、结束；语音状态只有实际设备 ready 后才显示监听/朗读。
- 保留键盘草稿和待手动发送附件，复用角色历史、批准记忆和 PPL；只保存完整成功聊天，不调用任务/文件执行。
- 每轮 30 秒监听、2000 字符；每场 20 个已完成回复轮次或 10 分钟。无语音、驱动或模型失败时结束，无后台重试。
- 听/想反馈接入既有 PetWidget 原生路径，仅自动播放已加载、已解锁、满足体力且音效明确为空的合适 random_act；用户交互优先，没有合适素材按既有气泡开关回退。说话仍使用原有 TTS 信号。

## 测试边界

新增 64 项：一句话识别 33、原生状态反馈 16、Qt 会话集成 15。音频测试替换物理驱动或设备边界，实际捕获循环、Qt/QThread、事件排队、本地 HTTP、聊天客户端与 SQLite 仍按生产路径运行。

Qt 集成检查两轮成功对话、第三轮监听、只有两次朗读、同场一个识别器、麦克风与 TTS 不重叠；请求带既有历史和上一轮回复，不带待手动发送附件。其他用例覆盖部分识别、停止已排队成功、阶段之间结束、生成/朗读打断、普通停止按钮、配置/角色变化、关闭、空语句、TTS 失败、20 轮、真实 QTimer 到期及固定控制条。

原生反馈测试执行从现有模块取出的实际 PetWidget 和 Interaction_worker 方法，观察真正的动作选择、current_img 和完成恢复；没有使用完整桌面导入。这证明调用与资源边界，不代表已在 Windows 桌面观察到真实宠物画面。仓库 Kitty/ChrisKitty 没有准确命名的听/想动作，预期回退气泡。

## 失败回归与集成修正

1. 识别器首轮 15 项因功能不存在失败；随后无效识别/PCM、停止和流启动清理边界先失败后修复，最终 33 项。启动异常也会关闭已创建音频流，流关闭期间的停止会丢弃已识别文字。
2. 原生反馈首轮 14 项失败；无效图像/时序、暂停/停止动画分支随后复现并修复，最终 16 项。
3. Qt 会话首轮 12 项因没有独立会话入口失败；核心两轮流程实现后通过。阶段切换后立即结束曾让“发送”等按钮残留禁用，补充断言先复现，再按当前忙碌状态统一恢复，包括已打开的试用窗口。
4. 首轮整批助手回归发现一条测试等待边界错误：HTTP 线程 flush 后立即取消，Qt 未必已显示增量。测试改为等待文本框实际收到部分回复，继续严格拒绝取消后的迟到增量。
5. 实际截图发现滚动到聊天时新语音控制组离开视口。800×600 的 Qt 回归先失败，再将原组移到固定顶部；保持同一套按钮与流程，没有添加重复控制器。

## 环境与整批回归

Linux 使用 `QT_QPA_PLATFORM=offscreen`、独立 `XDG_CONFIG_HOME` 和 PyOpenGL 3.1.10。Python 3.9 使用 Pillow 11.3.0，3.11/3.12 使用 Pillow 12.3.0。

```bash
QT_QPA_PLATFORM=offscreen python -X faulthandler -m unittest discover -s tests -v
```

首次三环境并行全量中，Python 3.12 的既有 Blender GLB 渲染子进程在采样日志中途退出，未给出可归因的原生错误；本批 63 项新增测试均通过。未改变渲染代码或放宽测试，同一失败用例独立运行 1/1 通过，再独立运行完整 860 项得到 855 通过、5 跳过。不能仅凭并行时间关系断言资源竞争是已证实根因；最终整批按环境依次运行。

## 独立审阅

一次独立整批审阅读取实际 controller → dialog → QThread 清理及 PetWidget → Interaction_worker 路径，没有发现 Critical、Important 或 Minor 缺陷。审阅者独立执行初始 63 项新增测试、后来加入的固定控制条回归，以及 8 个额外真实 Qt/HTTP 检查，均通过：监听/朗读打断后恢复；生成和朗读期间配置 A→B→A 不复活；旧生成/朗读停止按钮结束会话；空 HTTP 回复无朗读/历史；批准记忆和 PPL 快照进入请求而附件不进入。
