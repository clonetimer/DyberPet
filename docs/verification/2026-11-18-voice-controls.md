## 测试与失败回归

新增测试覆盖设备目录、选择捕获、完整播放、设置持久化及真实 Qt 会话。只在音频边界替换实体设备/驱动；生产捕获和播放循环、真实 Qt/QThread、HTTP 客户端与本地数据库保持运行。

1. 原 TTS 在实际回归中只读出 2000 字符的前 500 字符。新的分段实现覆盖全文、标点顺序、上限、唯一段名称、迟到/重复事件、第二段取消/错误和含初始化的总期限。
2. 设备解析原本跳过无效项后仍宣称唯一匹配；坏条目可能隐藏重名设备。回归失败后改为只允许完整目录证明唯一性，部分目录仍可带警告展示。
3. 宿主 `_submit` 的流式 `on_progress` 参数曾截走 TTS 段落回调；真实 Qt 用例失败后将 TTS 回调绑定在任务上，保留原流式 UI 通道。
4. 队列属性错误通过 error 事件记录，在 worker 抛出；先处理音色/语速配置并核验音色，再排第一段。测试确认失败配置不会说出默认音色。
5. 成功前缀后发生错误，原完成元数据曾保留 True；新增两种失败回归后，仅实际最后一段的 True 才可表示整条完成。
6. 独立审阅直接使用 [pyttsx3 v2.99 Engine.say](https://github.com/nateshmbhat/pyttsx3/blob/v2.99/pyttsx3/engine.py) 的固定版本方法，复现纯空白段不排队也没有完成事件。中间、开头、结尾与超过 500 个连续空白四种场景先超时，修复后均完成；审阅者再次用实际方法独立复核通过。
7. 既有试用 Qt 测试的三个严格设备替身未接受新增选项，导致 157 项 Qt 中三项失败。更新替身签名并保留原断言、补默认参数断言后，原试用 16 项通过；没有放宽结果或跳过用例。
8. 独立审阅在真实 Qt 中发现普通自动朗读的静态 100ms 回调可越过音频设置 A→B→A 的撤销。回归先复现实际播放，再改为窗口持有且可停止的单次 QTimer；保留手动朗读已显示回复，以及配置未变时自动读一次的正向用例。设置 Qt 13 项通过。

真实 Qt 会话新增三种生产播放路径：1200 字符三段全部完成、第二段停止、第二段错误；后一轮麦克风不会提前启动，错误/停止保留已显示回答，不再开麦。角色音色和麦克风参数传递另有独立断言。

首次 Python 3.9 全量在后续真实 HTTP 测试出现原生退出 139；下述有对照的生命周期修复后重新执行上述完整门禁，不把首次运行记为通过。

### Qt 夹具生命周期对照

原 `test_assistant_qt` 紧接 `test_assistant_request_control` 的 48 项自然执行通过，但在首个真实 HTTP handler 中仅加入一次诊断 `gc.collect()` 后退出 139。非拥有型弱引用追踪指出，`test_speech_engine_failure_retains_text_bubble` 的 `_submit` Mock 调用记录保存 `_speech_completed` 绑定方法，导致已关闭窗口仍存活，连同音频控件和会话对象在 HTTP WORKER 上回收；随后主线程崩溃。原生错误栈停在主线程读取响应处，不能据此把 HTTP 读取判作根因。

修复仅改既有 Qt 夹具的清理：close，等待尚存 worker，GUI 线程 `deleteLater()` 加 `DeferredDelete`。原 48 项通过（1.854 秒），相同单次 GC 压力的 48 项通过（1.946 秒）；追踪确认前述原生树在自己的测试清理中于 MAIN 销毁，后来被 WORKER 释放的 wrapper 已无原生对象。没有关闭 GC、改变顺序、放宽断言或修改产品信号逻辑。这个对照证明具体夹具漏洞；原全量日志没有 GC 探针，不声称捕获了原失败的确切回收时刻。

## 驱动与证据边界

[sounddevice 0.5.2 设备查询](https://python-sounddevice.readthedocs.io/en/0.5.2/api/checking-hardware.html)提供当前索引、名称与 host API，本版不宣称这些是硬件永久 UID。刷新只反映库当前目录；未使用私有 PortAudio 重初始化，热插拔后目录不更新时提示重启。

[pyttsx3 引擎 API](https://pyttsx3.readthedocs.io/en/latest/engine.html)定义排队属性、命名完成和 error 事件；具体行为同时核对 v2.99 固定源代码。已有 Linux eSpeak 2.99 后端的外部迭代兼容问题仍存在：[eSpeak iterate](https://github.com/nateshmbhat/pyttsx3/blob/v2.99/pyttsx3/drivers/espeak.py) 没有返回迭代器，而 [DriverProxy](https://github.com/nateshmbhat/pyttsx3/blob/v2.99/pyttsx3/driver.py) 外部模式会调用 `next()`。本批报告失败并清理，不添加私有驱动补丁，不把 Linux X11/打包冒烟解释成 Linux 真实语音可用。

实体 Windows 麦克风、中文识别准确率、系统音色听感、实际推理速度和长期性能需要对应硬件证据。本批没有声称全双工、唤醒词、声音打断、回声消除或音素级口型。第三方原生调用内部阻塞仍需等待其返回，300 秒是协作检查期限。
