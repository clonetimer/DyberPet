# R51：做好一个，再做下一个｜当前仅 Doro

## 唯一开发对象

Doro（朵拉 / Dororong）。用户认可的目标为 0x4682B4（六碳糖）的四足 Live2D 形象，见 https://booth.pm/zh-cn/items/5867617 和 https://github.com/MelanTech/Dororo 。

外观识别点：粉发、紫眼、玫瑰发髻、白色短四足身体、Q 版体态。R7 旧 Doro Codex 原画和程序绘制的四足 demo 不能当成这套目标原画。已经否决的低保真 3D 模型不回收再用。

**在这一角色真正完成前，暂停开发其他角色的新增美术。** 其他旧角色可以使用，但不能计入新完成数。

## 角色的完成判据（五关）

1. **原画身份**：明确作者、唯一造型版本和当前认可的 Doro 外观，并经过肉眼对照确认五官、发髻、配色、短四足轮廓。
2. **独立三视图**：同源正/侧/背三张独立原画，校验 SHA256 和禁止镜像/复制，三视角身份由真人核对。Live2D 的斜角变形不是独立背面。
3. **真实原生动作**：待机、左右四足行走、摸头、拖拽、下落、落地；左右走路每组至少两种不同可见姿态。检查自然步态、形体连续性。
4. **Windows 实机**：角色能在 DyberPet 本体启动、显示、缩放、点击、拖拽，经过 Windows 实际交互/高 DPI/关闭重启验收。
5. **授权交付**：源艺术作品可合法按目标方式交付；开源程序许可证不能代替模型作者和 IP 权利许可。

只有五关全部通过，状态才能成为“已完成”。自动哈希或软件测试成功绝不能代替人工美术核对。

## 当前阻断事实

- 0x4682B4 的 BOOTH 模型说明载明禁止模型再分发及用于 AI 生成艺术。不能未经授权放进公开仓库或私有下载仓库。
- 尚未获得、校验同一授权来源的完整正、侧、背三张独立原画；不能从既有 Live2D 前方动作伪造背面。
- 对应认可的 Live2D 版本在 DyberPet 中的真实原生动作与 Windows 实机尚未完成验收。
- 当前 R7 旧形象仅可作为功能试用，不称用户认可的 Doro 角色完成。

## 本轮新增：单角色真实验收工具

在已有合法获取、且已转换为 DyberPet native 格式的 Doro 角色目录中执行：

    python tools/doro_single_role_gate.py --role "res/role/实际Doro角色目录" --out DORO_STATUS.json
    python tools/doro_single_role_gate.py --role "res/role/实际Doro角色目录" --require-complete

第二条在任何门槛未满足时返回非零状态。该工具只读，不下载/修改/重绘/镜像/上传原画。

必须使用以下**真实证据**，而非以测试/伪造文件应付门禁：

- DORO_SOURCE.json：源作者、版本、目标参考（必须是六碳糖 Dororong）、四足体态以及非旧版冒充声明。
- Q_CHIBI_3VIEW.json：同一画师同一版本独立三视图 PNG 的 SHA256 校验。
- DORO_HUMAN_ACCEPTANCE.json：由真人实名或可追溯审核标识和具体备注，核对外观、三视图、四足步态、动作交互、Windows 实机和美术交付权限。

这些报告本身不证明作品是真实的，仍要查看原始图、逐帧动作和 Windows 桌面运行证据。

## 单角色路线

Doro 先达成真实外观 → 独立三视图 → 原生动作 → Windows 验收 → 合法单角色安装包，五关完成后才启动咕嘎。旧 65 角色继续可用，不再同时推进 65 套尚不合格的美术。
