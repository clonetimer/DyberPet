## 先看清单，不下载

在项目根目录打开 Windows PowerShell：

```powershell
python tools/personal_source_batch.py --output personal-role-plan.json
```

这一步只读扫描 `res/role`，列出“已结构安装”“有固定来源待确认”“需要手动导入”“仍缺来源”的区别。原画 Demo 不会冒充本人已安装的创作者素材。JSON 中的 `original_likeness_verified=false` 不会因为有哈希或结构化动作就自动改为 true。

## 在本机自愿安装（先尝试两个）

确认来源页面的使用条件，并备份已有 `res/role` 与个人设置后，再运行：

```powershell
python tools/personal_source_batch.py --install --accept-personal-use --max-roles 2 --output personal-first-2.json
```

你也可以只选一个原神模板：

```powershell
python tools/personal_source_batch.py --profile genshin_nahida --install --accept-personal-use
```

查看首批两个角色的脸型、服饰、发饰、动作及缩放显示，若满足你的个人需求再执行：

```powershell
python tools/personal_source_batch.py --install --accept-personal-use --output personal-full-install.json
```

此命令会尝试尚未安装且有支持的固定来源的人物，各人物默认选已有优先级排序里第一个可以自动导入的来源。下载/转换采用项目现有的精确来源版本、内容哈希及原生动作审计。来源不能访问、数据损坏或超出大小限制时，逐项报告失败，不覆盖用户旧角色。经过完整源文件 SHA-256 与原始帧核验的 React LFS 人物（安柏、菲谢尔、那维莱特、莱欧斯利）现可经用户明确确认后自动本机下载；其他只有 LFS 指针的候选仍不得自动安装。尚缺固定来源的 55 个模板仍无可证明的作者动画。

**批量安装不会对作者许可作出判断。** 不要在不允许的情况下抓取或使用第三方素材。用户选择的来源必须符合各自的使用条件。安装完成也仅说明素材已通过程序结构校验，需要亲自进行人物视觉、动作和声线核对。

## 不要把个人素材推回 GitHub

脚本只把图片保存到本机指定的 `--role-root`（默认 `res/role`），不提供上传功能。仓库忽略 `/res/role/Source*/`，但其他手动导入目录未必被忽略；提交前执行 `git status --short`，检查是否有图片、音频、用户配置等文件。切勿执行 `git add -f` 将第三方素材强行提交。

上述命令属于源码入口；从 R13 起，Windows 便携版已提供「角色管理 → 安装作者原画」的图形界面批量入口。请从与当前候选提交匹配的 GitHub Actions 成功产物下载；Windows 实机外观与长期桌面运行仍需人工复核。

## R13：无需命令行的本机批量补齐入口

R13 将原有已验证的本机批量安装接口直接接入 **DyberPet → 角色管理 → 安装作者原画**。点选“批量补齐：本机尚未安装、具有固定作者来源的全部原神人物”，或先选择“先试装 2 位”检查网络与角色形象。明确阅读并确认第三方艺术作品的个人使用限制后，才允许下载；拒绝或取消会保持本机文件不变。此操作**不会把 65 套原画预先包含进 GitHub ZIP**。

安装过程在独立 QThread 中进行，界面显示当前人物编号、正在安装的身份和固定来源失败提示。按“完成当前人物后停止”不会杀死图像转换或留下半写入角色；只在**下一位人物开始前**生效。每一位人物只允许读取当前已固定校验的同身份来源，不会把 A 人物素材错挂 B 人物，也不会静默退回程序简笔演示。

批量完成后，程序对实际 `res/role` 目录进行角色库复核，显示「尝试 / 实际认可的本机原画 / 失败」三项数字，并把**每个人物和每个候选来源的详细结果**写在便携目录 `data/personal65-batch-YYYYMMDD-HHMMSS.json`。这份报告只存在用户本机；保存失败会在界面如实提示。新增角色需重启 DyberPet 才能被完整加载。可从角色库逐帧查看动作；下载、配置和文件结构校验成功并不等于人物外观或动作自然性已经人工确认。

原神角色模板数为 123，固定来源覆盖为 65，58 位仍缺；批量工具**只尝试**有固定来源而尚未安装的人物，不能凭这一按钮补全不存在的素材、原声音频或许可证。一次下载几十位角色可能耗时较久，并受第三方站点网络限制；因此建议首次先试装 2 位。

## R14：每位人物及时保存结果，以及不重启预览新增原画

R13 的批量任务结束时才保存报告，突发关机或窗口中断会丢失此前的角色安装过程记录。R14 改为每处理完一位人物，就由工作线程将**暂定结果**原子写入 `data/personal65-batch-YYYYMMDD-HHMMSS-XXXXXXXX.json`。每次写入先生成同目录临时文件，刷新到磁盘后用 `os.replace` 完整替换，不上传用户素材或结果。突发中断后这份文件仍保留已经写入的进度；`finished=false` 表示需重新盘点本机库，`pending_inventory_validation` **不代表成功安装或原设通过**。任务正常结束才用完整本地库扫描结果写入最终报告。

批量完成后会弹出真实安装计数。点击“立即查看”可选择本轮结构验证通过的角色，**直接打开刚安装的完整 PNG 动作逐帧预览，无需重启软件**。这个预览只读取本地库存确认的原生素材文件夹，不修改当前桌宠，也不自动把未初始化的数据加入运行时。要将新增角色正式设为桌宠，仍建议重启 DyberPet。

如果便携软件安装目录没有数据写权限，系统明确显示“本机进度保存不可用”的警告，下载/转换不因日志路径错误而误报成功。建议解压到本机用户拥有写权限的目录，不要放在 Windows `Program Files` 之下。

## R15：一键续传上次中断或失败的真实角色原画

在 **角色管理 → 安装作者原画 → 查看上次进度并续传未完成或失败的真实原画** 中，软件只读检查便携目录 `data/personal65-batch-YYYYMMDD-HHMMSS-XXXXXXXX.json`，不会自动联网。读取过程限定已知命名、文件大小和预期 JSON 结构；拒绝符号链接、无效报告和异常结果。

- **上一次非正常中断**（日志 `finished=false`）：重新扫描当前 `res/role`，只继续那些至今仍未结构安装、且有项目固定来源安装器的人物。即使上次下载后尚未保存最终报告，只要当前角色库已经认可其原生动作，就不再重下。
- **上一次正常结束但有部分失败**（`finished=true`）：从完整安装报告中筛选确实失败的人物，再与最新原画白名单及角色库做交集。已成功安装、无可信来源或从未在上次任务中失败的人物均不会被选为重试目标。
- 若没有有效日志，提示用户使用“先试装 2 位”或“批量补齐全部”；不会依据文件名猜测已完成角色，也不会凭旧日志绕过固定来源。
- 选择续传之后，仍会重新显示第三方素材使用确认对话框；**只有明确同意才会执行网络下载**。执行时继续逐角色原子保存，新结果写入全新日志，不覆盖旧历史。

这项恢复功能是基于**新鲜原生角色库盘点和固定来源的重新计划**，并不是把上次中断的半个 ZIP 当作完整图片使用；网络站点不可达时仍会诚实记录失败。还原角色外观、运动自然性、语音与作者授权均不因“续传成功”而自动认证。

## R16：中断恢复必须遵守用户原来的试装范围

R15 的早期中断恢复根据全体当前可安装角色重新规划，未记录用户在上一次任务究竟选择了“先试装 2 位”“只选指定角色”还是“批量全部”。这可能让少量试装的续传扩展为更多下载。R16 修复此问题：

- 启动批量任务前，先按真实待安装角色顺序与 `max_roles` / 指定角色过滤，记录精确 `planned_profiles` 到本机原子日志。网络请求前记录范围，首次下载前中断也不丢失约束。
- 新日志中断后，只在**原来明确选定**且**目前仍未安装**、**仍有固定来源**的人物范围内恢复；不会因为其他角色后来有来源而额外安装。
- 兼容旧 R14/R15 日志。旧日志没有记录完整选中范围，因此只能安全地重试日志中**已经尝试过**但当前未安装的人物，无法证明用户同意的其余未尝试角色不得自动追加。需要完整批量时，用户可手动重新选择“批量补齐全部”并再次明确确认。
- 已正常完成任务的 R15 逻辑不变：只重试最终报告中的失败人物，并与最新来源白名单、已安装角色清单再次取交集。

续传仍需显式同意；该修复不会打包、上传或认证任何第三方原画。
