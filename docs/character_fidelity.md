# DyberPet 多角色“贴近原设”专项（P3）

**状态：验收框架已接入，真实角色美术/专属原声尚未验收。** 技术检查通过不等于原作相似度或分发许可成立。角色导入流水线 PR #1 仍暂停；此工作仅属于桌宠功能 PR #2。

## 四项独立验收

| 维度 | 自动化可检查 | 必须由人工对照特定作品/版本检查 |
|---|---|---|
| 视觉 | 动画 PNG 存在性、尺寸、原生动作配置 | Q版轮廓、服装、发型、角色标志以及比例 |
| 动作 | 待机、移动、休息、互动、说话等动作文件名及帧数 | 运动风格、连贯性、贴地/悬浮、口型是否真正同步 |
| 人设 | 独立 PPL/LMStudio 提示词模板与选择流程 | 剧情适配、角色语气、不照搬完整官方台词 |
| 声音 | 本地 WAV 格式、作者来源记录和 SHA-256 | 具体语种配音、音色、声画同步与使用授权 |

## 软件操作

安装用户合法取得的 DyberPet 角色包后，在角色上右键 → Desktop Pet Assistant。

1. 角色名称精确解析咕嘎、Doro、派蒙、纳西妲、可莉、芙宁娜和阿丽莎，载入对应人设与审查清单。陌生角色仍使用通用人设，不因为出现名称片段就自动归类。
2. 点击“核查当前角色”：读取实际安装目录下的 pet_conf.json、act_conf.json 及 action PNG 帧，展示动作覆盖与该角色的辨识点。缺少角色包时清晰报错；报告**永远不自动声称已还原原作**。
3. 点击“登记本地授权 WAV”：人工选择短音效、填写实际作者及具体 HTTPS 来源，并确认获得本地使用权限。
4. 点击“试听已登记音效”：音效记录按照角色档案独立存放；跨角色串换记录或音频发生变化会拒绝播放。该短音效不用于自动训练模型或合成任意台词。
5. 本地 LM Studio + PPL 支持各自风格的文字对话，pyttsx3 只提供普通本机朗读，**不等于角色官方原声**。

## 自助技术审查

以下命令仅在已安装对应角色、具备使用权时有意义：

    python tools/audit_character.py --character Doro --role "res/role/Doro" --report "D:\PetQA\Doro_report.json"
    python tools/audit_character.py --character 派蒙 --role "res/role/Paimon" --wav "D:\PetQA\Paimon_sound.wav"

输出 JSON 包含 character/profile、frame coverage、静态缺口以及原设视觉/动作/声音逐项人工核对标准；真实性字段始终为 not_verified。软件无法从文件名自动判断相似度。

## P4：桌宠运行期动作差异（新增）

本轮不导入第三方素材，只在 **DyberPet PetWidget 原生移动链路** 上加入两个克制的角色行为策略：

- **Doro 四足运动策略**：原生动画系统确实产生地面水平移动时，将每帧 x 位移乘 1.3；鼠标拖动或离地时不调整。策略名称为 `quadruped`，用于适配活泼的四足角色速度，**不能凭借速度参数生成真实四足步态图**。真实性报告额外要求左右方向各至少四帧，缺失时明确列出。
- **派蒙悬浮策略**：原生 PetWidget 仍保留正常动画工作线程，但在初始化位置将角色提升约 34 像素（按缩放调整），采用周期 2.4 秒、幅值最多 8 像素的非累积上下浮动。拖动、抛落时暂停附加浮动，并限制回到底边界以下；切换到普通角色关闭定时器。它是窗口位置的轻量补偿，**不等于原版悬浮、面部/发丝/服装动画**。报告对不足两帧的待机图片予以提醒。
- 其余角色仍保留原版 DyberPet 运动行为，不强行叠加 Doro 或派蒙的效果。所有计算仅改变窗口几何和现有移动增量，不生成或下载新的游戏资源，不绕开已解锁动作。
- **用户可控**：桌宠助手新增“角色运动增强（Doro步速／派蒙悬浮）”复选框，默认启用。若所安装的作者动画已经具备完整位移，可直接关闭；关闭派蒙悬浮时位置返回屏幕地面，不留下定时器。设置保存在本地 `assistant.json`，也可再次开启；未选择的旧版配置继续使用默认值。

**范围说明**：P4 实现的是主角色 `PetWidget`（`res/role`）；P5 另外实现了 `SubPet`（`res/pet`）迷你宠物的受限悬浮行为。它们调用不同的运动与跟随机制；二者分别测试，不能凭其中一类的结果替另一类验收。

回归验证包括行为函数数值边界、派蒙完成一个浮动周期后不发生位置漂移、拖拽/坠落期间暂停浮动、Doro 只有地面主动移动时改变步速、切换角色后停用悬浮。部分测试通过隔离编译 PetWidget 的**真实方法体**进行集成验证，而不是仅测试一个无关的辅助函数；完整 Windows 实机的重力/多显示器/动画视觉效果仍需人工验收。
## P5：派蒙迷你宠物悬浮与原生动作兼容

本轮直接改动现有 `DyberPet/Accessory.py` 的 **SubPet** 类，而不是仅在人物说明中声明支持。技术范围如下：

- `isSubpet=True` 且角色确切识别为派蒙，同时 `follow_main_y=False`（迷你宠物以地面为基准、可在 X 轴跟随主角色）：使用独立的 80ms Qt 计时器执行绝对位置悬浮目标，离地约 34 像素，周期 2.4 秒、幅值最大 8 像素，并限制每次位移最多 4 像素以减少跳动。
- 原来的 `follow_main_x`、水平排队、随机动画和掉落逻辑继续运行。悬浮补偿只设置窗口 Y 坐标，不改写跟随目标或动画帧。
- 对 `follow_main_y=True` 的迷你宠物，作者已经给出了完整 X/Y 跟随目标，**不叠加**悬浮计时器，以免两个控制器互相争夺 Y 坐标。正常角色、非 `isSubpet` 的附属宠物也不会启用迷你悬浮。
- 鼠标拖拽、抛落、窗口不可见或关闭过程中停用悬浮输出。关闭迷你宠物时停止新增和原生两个 timer；当前会话可通过其右键菜单“暂停悬浮/启用悬浮”来切换，关闭后回归当前屏幕底线。
- 默认值读取用户的 `assistant.json → motion_enabled`，与主角色运动开关一致；迷你宠物右键切换仅影响该实例的当前会话，不修改全局设置。已打开迷你宠物不会因对话窗口临时修改勾选框而立即被覆盖。
- 修复原生 `PetConfig.init_subpet()`/`init_config()`：可选动作不再强行索引字面名称 `default`，而是引用 `pet_conf.json` 中指定的实际待机动作。迷你宠物 `prefall` 缺省时也返回真正的 Act 对象，不再返回字符串。

自动化测试通过 AST 提取并执行 SubPet / PetConfig 的真实实现方法，在不依赖第三方美术资源的条件下验证：漂浮限速和周期、拖拽暂停、坠落暂停、仅跟随 X 的保真、同时跟随 X/Y 时不启动 timer、关闭后资源清理，以及自定义默认动作名的兼容性。

**非程序员检查入口**：桌宠助手新增“检查派蒙迷你宠物（res/pet）”。即使当前主角色是 Kitty，也可检查用户已经安装的派蒙迷你宠物；如果本地不存在相应目录会明确提示，而不是默认为可用。若安装了多个符合名称规则的派蒙迷你宠物，会允许选择具体目录。报告分别显示跟随 X/Y 轴的真实配置及额外悬浮适用性。这个界面只读取本机原生配置，不安装素材。

本地脚本亦可对迷你宠物角色帧执行基础静态检查：`python tools/audit_character.py --character Paimon --role "res/pet/Paimon"`。这只检查图像和动作的存在性；**跟随行为**以桌宠助手内的迷你宠物专用检查为准。

**剩余界限：** 这仍不是派蒙原版悬浮动画，不涉及真实口型、动作帧、透明边缘和音效质量。Windows 实机的真实素材、多屏幕、DPI、鼠标拖拽及语音声画同步仍需人工验收。未经授权的派蒙动画和原声没有加入工程。
## P6：Doro 实际步态来源门禁与语音/气泡联动

本轮针对 Doro 修复了此前的实际行为缺陷：1.3 倍步速原来可能影响所有水平移动，包括部分交互动作。现在原生 `Animation_worker` 只把 `pet_conf.left/right` 引用的、带左右方向、至少四张**不同图片**的移动动作发到独立 `sig_move_native_gait`；其余动画和 `Interaction_worker` 的移动继续走普通通道。`PetWidget._move_native_gait` 仅在 Doro、启用了角色运动增强、角色处于地面且未拖拽时应用额外步速。可见的四足迈步依然依赖作者提供正确的帧；帧数不代表真实四足动作已经通过美术审查。

朗读开始/结束和角色视觉状态也已同步接入。按用户选择的 `pyttsx3` 本机朗读开始时，桌宠显示当前回复气泡，并且仅在本机已有、已解锁且明确命名为 `talk/speak/说话/讲话/口型` 等说话动作时调用原生交互调度器 `_show_act`。没有这种动作时**只显示气泡并继续语音**；不会凭空生成新的嘴型，也不采用匹配到子串的非说话动作。朗读结束、服务失败、关闭对话框或切换角色会清除视觉上的说话状态。自动朗读启用后，回复气泡会在请求本机朗读时显示，而不是在模型文字生成时提前展示。

**与真正唇形同步的区别**：这是朗读生命周期到现有动作的一次触发，不包含音素对齐、口型逐帧追踪、TTS 时长驱动的精确动画循环或声纹识别。尤其对官方配音尚未取得许可的角色，不能把本机默认音色称为原声；Windows 声音设备和完整美术组合仍待实机验证。
## 合并和真实发布阻断

- 无实际合法美术/动画，不能宣称形象完成；无具体音源许可，不能随源码分发角色声效。
- 只有系统 TTS，不能称原声；短 WAV 仅供本地试听，不能作为完整语音克隆模型。
- 目前未实现自动唇形同步、骨骼动作重定向和版权真实性的算法验证；需要 Windows 实机视觉/听觉人工验收。
- 优先处理 Doro（特殊四足体态）和派蒙（特殊悬浮体态），再推进其他角色的实际素材对照；不因为测试通过就合并 main。
