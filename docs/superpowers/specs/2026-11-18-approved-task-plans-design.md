# 本地 AI 任务草案与逐步审批

## 意图和范围

延续 PR #99：让用户把一句要求变成可查看、可取消的文件任务草案，再亲自批准每一步。普通聊天仍然只回复文字。本批沿用 Python 3.9+、PySide6 和 loopback LM Studio，增加最多 5 个新建文本文件的顺序任务。用户的“记录开发经验，继续推进”授权本批实现与更新现有分支；PR 保持 Draft。

## 方案选择

1. 从普通聊天中提取工具标记：容易把引用和截断文本当作动作，且现有聊天只有 2,000 字符预算。
2. 独立的结构化草案请求，再由本地严格验证和逐步审批：本批采用。与 LM Studio 的 `/v1/chat/completions` JSON Schema 输出兼容，普通聊天路径无需改变。
3. 自主工具循环：当前没有必要引入；难以让用户在执行前检查所有写入内容。

这是本轮实施选择，不表示用户逐项指定了接口或限额。模型不支持结构化输出、返回截断/无效结果时明确失败，不回退为解释自然语言指令并执行。

## 数据与边界

唯一协议：`{"version":1,"title":"任务名称","steps":[{"action":"create_note","name":"笔记.md","content":"完整内容"}]}`。

- 严格 JSON；拒绝重复键、未知字段、Markdown 包裹、非整数版本、非法 Unicode、无效类型。
- 标题 1–120 字符；1–5 步；动作仅 `create_file` / `create_note`。
- 文件名通过现有 `PetWorkspace.validate_name`，不允许规范化后与原名不同；禁止控制/格式字符，跨平台大小写重复名称拒绝。
- `create_note` 仅 `.md/.txt`；`create_file` 沿用 `.md/.txt/.json/.csv`；每步内容最多 8,000 字符，总计最多 16,000 字符，JSON 文本最多 128 KiB。
- 解析不读取目录、不申请权限、不执行动作。计划和步骤不可变。
- 规划请求仅发送用户当前要求及本次已明确批准的文件参考；参考放在用户数据角色中，系统说明其不可信。无目录扫描；不自动读取聊天、记忆或磁盘。
- 只接受 `finish_reason=stop` 且无 tool_calls/refusal 的完整模型回复；网络继续使用现有禁代理、禁跳转、loopback 限制。

## 执行和界面

输入框新增“生成任务草案”；结果以独立非模态窗口呈现任务名称、绑定目录、每步状态、当前目标绝对路径、完整只读文件内容。用户点击“批准并执行此步”只执行当前步骤；下一步必须另行点击。

`TaskSession` 仅按需 prepare 当前一步，复用现有 `ActionRuntime` 的一次性 60 秒审批和本地审计。不会预批准整个计划。取消/失败停止剩余步骤；已成功创建的文件保留，报告准确完成数及文件名。过期需要重新生成草案；成功后的审计故障显示警告，不重试文件动作。

计划绑定角色、工作区对象和会话版本。角色切换、工作区授权/撤销、清空会话、关闭窗口或替换计划立即作废旧草案和未消费审批。关闭模型请求中的窗口时立即使旧结果失效，等待线程结束后关闭。迟到成功和错误均不能污染新会话。

运行时在准备、授权、执行和工作区切换时保持锁的一致边界，执行使用已审批的工作区，防止路径预览与实际目标分离。

## 验证与交付

纯 Python 行为测试覆盖严格解析、无审批不写入、逐步推进、拒绝/失败/过期、不可变内容、目录切换、重放和部分完成。Qt 离屏测试检查真实控件、完整内容预览、按钮一次只写一文件和旧会话结果丢弃。模型传输测试使用真实回环 HTTP 服务验证请求结构与错误路径；不据此宣称真实模型质量。

记录开发经验，更新使用文档；本地先验证，再一次推送完整批次，核验对应 SHA 的 Desktop CI 和 Windows 候选构建。语音硬件、真实模型成功率和 CPU/GPU/FPS 尚须设备实测，不在本轮模拟通过。
