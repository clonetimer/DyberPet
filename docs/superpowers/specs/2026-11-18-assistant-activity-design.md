# 可停止的助手请求与真实活动反馈

日期：2026-11-18；起点：`9945a311cdfe60532e8d136c33cb4103217cd2ba`。

## 目的与授权

用户要求“记录开发经验，继续推进”。沿既有本地桌宠主线，本批由开发者选择补齐生成、监听和朗读的可控交互，不另开产品方向。继续在现有分支和 Draft PR #99 交付，不合并或发布。

已有逐步文件审批、连续监听和可中断朗读，但模型请求无法主动停止；状态文案混合了工作准备、实际活动和结束结果。模型等待还会拖延关闭窗口。上一批的会话隔离需要延伸到主动取消。

## 方案与选择

| 方案 | 收益与代价 | 本批决定 |
| --- | --- | --- |
| 仅隐藏迟到的结果 | 改动少，但底层请求仍阻塞，不能尽快再次发送 | 不采用 |
| 在线程中协作取消，并中断当前本地 HTTP 套接字 | 不引入依赖，保留线程与现有权限边界，需要处理头部/正文阻塞及完成竞态 | 采用，由开发者作出的实现选择 |
| 重写为异步网络或独立模型进程 | 可支持更复杂调度，但引入较大结构变更 | 留待有具体需求时评估 |

## 使用行为

- 聊天和生成任务草案期间显示“停止生成”。点击后立即停止接收结果，显示正在停止；工作线程真正退出后才恢复发送按钮。
- 聊天保留已显示的片段并标记为用户停止；片段不作为完整回复保存到历史，不自动朗读。原问题在输入框仍为空时恢复，用户期间输入的新文字不被覆盖。已批准附件保留供重试。
- 取消任务草案不会打开审阅窗口、创建文件或消费附件。角色、人设、目录和窗口变化仍清除旧作用域资料，并主动取消其网络请求。
- 活动状态与普通操作提示分开，显示当前工作、经过时间、聊天首段等待时间及已显示字符数。这些是本次本机请求的观察值，不是模型性能评级，不持久化提示词、回复或音频。
- 麦克风只有在输入流成功打开后才显示正在监听。停止期间不再由部分识别覆盖状态；正常停止仍把最终识别文字交给用户检查后发送。
- 朗读初始化阶段收到停止时不继续排入语音；迟到的 ready 信号不启动气泡或动作。气泡开关适用于手动与自动朗读，动作继续使用已有、已解锁资源。

## 实现约定

- 新增 `CancellationToken`、`RequestCancelled` 和可取消的本地 HTTP 请求上下文；可选 `cancel_token` 参数贯穿 JSON 请求、流式聊天、草案生成和聊天前的 PPL 状态读取。
- 保留现有无 token 调用兼容性；所有 HTTP 仍只接受明确配置的 loopback 地址，不使用代理，不跟随重定向；响应上限不放宽。
- 工作线程拥有响应/连接的关闭。取消仅设置线程安全状态并 shutdown 正在等待的 socket；不 terminate Qt 线程，不从 UI 调用音频驱动。
- UI 统一持有当前请求 token、工作种类、取消标志和单调时钟指标；信号回调核对当前会话及请求状态。停止后即使成功信号已排队也不能提交历史、朗读或创建审阅。
- 声音准备/实际就绪/停止分别有状态；麦克风 ready 信号绑定本次 stop event 与角色/会话，避免旧信号误伤新任务。
- 支持 Python 3.9/3.11，现有 Windows Qt 6.5.2 与 Linux Qt 测试，不新增生产依赖。

## 验证与边界

真实回环 HTTP fixture 验证响应头等待、SSE 正文等待、JSON 正文等待及取消后连接释放；Qt 事件循环验证停止、重试、关闭、迟到成功/错误和部分回复。离线语音使用可控假驱动验证就绪与停止顺序，不声称实机音频通过。原生桥接测试只验证实际方法的气泡/动作控制。

只做本批行为所需回归与一次完整套件；独立审阅后将完整代码一次同步到既有 PR，验证对应提交 CI。真实模型质量、麦克风/TTS 硬件、CPU/GPU/FPS 与长时间运行仍待设备验收。
