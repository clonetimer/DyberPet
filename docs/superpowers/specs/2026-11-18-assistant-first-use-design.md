# 桌宠助手首次使用闭环

## 目标与接续依据

接续 PR #99 的 `069d6d4`：流式对话、记忆、连续语音、审批任务和取消机制已有实现。本批完成上一对话明确的下一步：模型选择、连接失败提示、语音就绪状态。用户要求直接推进、每阶段记录经验；本设计中的接口与呈现细节由实施者决定。

## 实施选择

沿用 PySide6 助手窗口、单一工作线程、现有本地 HTTP 与配置文件。选择在现有设置区加入可编辑模型下拉框和独立检查状态；独立安装向导会重复配置，全面重排助手窗口会扩大本批范围，因此暂不采用。

- “检查连接 / 刷新模型”仅在点击后请求当前地址的 `/v1/models`，不发送对话、附件、记忆，不加载模型，不自动保存设置。
- 模型列表称为“服务列出的模型”，不宣称均已加载或可以聊天。LM Studio 的 JIT 模式可能返回全部已下载模型：[官方说明](https://lmstudio.ai/docs/developer/openai-compat/models)。保留手填 ID；已有选择不被刷新覆盖；只有一个候选且输入为空时自动填入。
- 列表与状态绑定请求时的地址和本次检查标识。地址变化、取消、关闭或旧任务返回不得覆盖新配置；保存仍使用原有 `llm_model` 字符串。
- 区分地址不合法、服务未启动/连接失败、超时、HTTP 状态、空列表、响应无效。以中文提示可执行的下一步，保留必要原始错误，不能将认证失败引导为关闭认证。
- 语音检查只检查模块可发现性和用户指定的模型目录标识，不导入驱动、不加载 Vosk、不打开声卡、不录音、不发声。识别与 TTS 状态分开；组件存在不表示设备已验收。
- 识别目录兼容 Vosk 当前布局 `am/final.mdl` + `conf/model.conf` 及旧布局 `final.mdl` + `mfcc.conf`，仅检查结构，实际加载仍以原语音执行结果为准：[Vosk 源码](https://github.com/alphacep/vosk-api/blob/master/src/model.cc)。
- 配置缺失时发送/生成草案保留输入和附件，给出定位提示；有效手填配置无需先检查也能发送。

## 全局约束

- Python 3.9+；保留 PySide6 6.5.2 兼容性；不增加运行时依赖。
- 仅 loopback HTTP，拒绝代理、重定向和非本地地址。
- 不自动打开麦克风、不自动发送识别文本、不自动下载模型、不启动外部服务。
- 保留既有角色隔离、工作区授权、文件逐步审批、取消与 Qt 生命周期。
- 每阶段更新 `docs/DEVELOPMENT_EXPERIENCE.md`，含改动、原因、踩坑和证据边界。

## 验证与交付

真实回环 HTTP 验证发现、错误与取消；Qt 事件循环验证控件、地址竞态、输入保留和重试；语音检查验证不触发设备。一次完整回归和独立代码审阅后更新既有 PR，核验新 SHA 的远端 CI 与便携包。实机音频、模型质量和 CPU/GPU/FPS 仍是独立设备验收，不以模拟结果宣称通过。
